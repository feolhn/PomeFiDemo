# PomeFi AI 理财 App PRD v0.3.0（Streamlit Demo 版）

> 版本定位：面试展示用 Streamlit Cloud Demo 版本\
> 核心目标：将原有系统架构思想，压缩为“前端展示型 MVP”\
> 本版本不构建完整后端架构，仅实现 Skill 卡片预览闭环。

---



# 一、核心目标

将 PRD 的最终实现方式，转化为 **Streamlit 前端页面 Demo**，仅实现前端展示效果（无需完整后端架构与数据层拉通）。

核心落地目标：

> ✅ Skill 卡片预览功能完整跑通\
> ✅ 图表效果达到展示级质量\
> ✅ 可部署至 Streamlit Cloud 用于面试展示\
> ❌ 不实现完整 Skill OS 架构\
> ❌ 不实现社区系统\
> ❌ 不实现用户体系

风格要求：

- 模仿 shadcn/UI 极简风
- 主色调：黑 / 白 / 灰
- 大量留白
- 圆角卡片
- 弱边框
- 低饱和度标签
- 强层级排版

视觉关键词：

> 冷静、理性、极简、结构化

## 3. 核心功能（唯一真实逻辑模块）

仅 Skill 卡片预览模块需要真实数据调用。

其他页面全部使用 Mock 数据展示。

---

## 4. 数据参考规范

页面测试输入 / 输出内容必须严格参考：

- input\_mock.md
- output\_mock.md

注意：

- 仅参考数据内容
- 不参考 Markdown 排版
- JSON 字段结构必须一致

---

## 5. 图表视觉要求（重点）

Skill 卡片中的图表必须达到“出彩”效果。

可使用：

- Plotly
- Matplotlib（高级美化）
- 其他支持交互的绘图库

必须满足：

- 支持悬停显示明细数据
- 黑白灰风格适配
- 字体与图例优化
- 图表自适应布局
- 卡片内视觉居中
- 适配不同屏幕尺寸

图表为核心视觉锚点。

# 三、Skill 卡片功能设计（核心模块）

## 1️⃣ 数据流流程

数据流程为硬编码调用流程：

Akshare（抓取指定标的）\
↓\
数据清洗\
↓\
传入 Kimi API\
↓\
接收结构化 JSON\
↓\
转化为卡片渲染结构\
↓\
生成可视化图表

---

## 2️⃣ 测试输入（必须固定）

严格使用 Mock 输入：

trend\_follower：

- 股票代码：300750（宁德时代）

fund\_diagnostic：

- 基金代码：001410

stock\_diagnostic：

- 股票列表：
  - 600519
  - 002594
  - 600036
  - 601012
  - 601318

---

## 3️⃣ 输出内容要求

卡片必须完整展示 JSON 返回字段，包括：

- 基本信息（必需）
- 核心结构模块（按 Skill 类型动态变化，如行业分布 / 估值区间 / 新闻时间线等）
- 风险或结构解读（若该 Skill 包含）
- 用户画像匹配度（如该 Skill 涉及画像）
- 数据来源
- 生成时间
- 质量状态

说明：
不同 Skill 的输出字段允许存在差异，不强制每个卡片包含完全相同的模块结构。字段必须与 output\_mock.md 中对应 Skill 的定义保持一致。

不可省略字段。

---

## 3️⃣ 输出文字风格规范（新增）

参考 output\_mock.md 的表达方式，Skill 卡片内所有分析性文字需保持统一风格。

具体要求：

1. 语气基调

   - 冷静、克制、理性
   - 不煽情
   - 不口号化
   - 不鸡汤化

2. 语言风格

   - 类似投行研究报告的判断口吻
   - 允许轻微毒舌或黑色幽默
   - 使用短句增强节奏感
   - 避免网络用语

3. 评价逻辑

   - 必须基于数据
   - 先给事实，再给判断
   - 先给结构，再给风险
   - 不使用“强烈推荐”“必涨”等表述

4. 风格示例方向（抽象表达，不写具体案例）

   - “你看上去买了一箩筐基金，其实都一样。”

5. 禁止事项

   - 不使用情绪化夸张表达
   - 不使用明显营销语言
   - 不出现投资建议语气

目的：

> 让 Skill 看起来像一位理性、略带锋芒的华尔街分析师，而不是一个热情的财经博主。

---
