# 六-A、Streamlit Demo 实现方案（面试展示版）

## 一、核心目标（Demo版）

将 PRD 的最终实现方式，转化为：

> 基于 Streamlit 的前端展示版本

仅实现前端 UI 展示效果，不拉通完整后端架构。

核心目标：

-   ✅ 落地 4 个一级页面 UI
    
-   ✅ 实现 Skill 卡片预览功能（唯一真实功能模块）
    
-   ✅ 可部署至 Streamlit Cloud
    
-   ✅ 面试时可直接打开访问链接演示
    

本版本为：

> 产品表达验证版本（非生产系统版本）

----------

## 二、页面开发要求（Streamlit版）

### 1️⃣ 一级页面结构（共 4 个）

使用 Streamlit sidebar 或 tab 实现：


| 页面 | 对应PRD模块 | 实现要求 |
| -------- | ------- | -------------------- |
| 消息 | 社区动态流 | 仅展示 mock Skill 卡片和动态流 |
| Skill实验室 | 创作中心 | 可触发 Skill 卡片生成 |
| 聊天 | 群聊结构空间 | mock 聊天界面 |
| 主页 | 个人结构中心 | mock 用户画像与 Skill 小组件 |

要求：

-   仅做 UI 展示
    
-   不接入 Core / API / Registry 架构
    
-   不实现真实数据库
    
-   不构建完整 Skill OS
    

----------

### 2️⃣ 视觉风格要求

-   参考 shadcn/UI 风格
    
-   主色调：黑 / 白 / 灰
    
-   极简排版
    
-   卡片式结构
    
-   强调层次感与结构感
    

不使用艳色系。

目标风格关键词：

> 冷静、理性、结构化、科技感

----------

## 三、Skill 卡片预览功能（唯一真实模块）

这是 Demo 版本唯一需要真实运行的数据流模块。

----------

### 1️⃣ 数据流程

硬编码股票代码  
↓  
Akshare 获取数据  
↓  
传入 Kimi API  
↓  
Kimi 返回结构化文本  
↓  
整理为 JSON  
↓  
生成 Skill 卡片 UI

----------

### 2️⃣ 技术实现要求

必须满足：

-   直接在 Streamlit 中调用 Akshare
    
-   直接调用 Kimi API
    
-   不经过 Core / Registry / Engine Adapter
    
-   不构建完整 schema 校验系统
    
-   仅生成 JSON 结构并展示
    

----------

### 3️⃣ 卡片展示要求

卡片必须完整展示：

-   API 返回的全部 JSON 字段
    
-   包括：
    
    -   标题
        
    -   分析段落
        
    -   时间线
        
    -   风险提示
        
    -   估值区间
        
    -   用户匹配度
        
    -   数据来源
        
    -   时间戳
        

要求：

-   使用 Streamlit container 模拟卡片样式
    
-   可折叠区块
    
-   信息层次清晰
    
-   视觉接近 PRD 描述
    

----------

### 4️⃣ 交互体验

基本交互包括：

-   输入框（股票代码）
    
-   点击生成按钮
    
-   loading 状态提示
    
-   卡片展示
    
-   JSON 原始结构可展开查看
    

----------

## 四、部署要求

### 1️⃣ 部署平台

-   Streamlit Cloud
    

----------

### 2️⃣ 交付形式

必须交付：

-   ✅ 可公开访问的 Streamlit Cloud 链接
    
-   ✅ 页面打开无报错
    
-   ✅ Skill 可正常生成卡片
    
-   ✅ 可在面试中直接演示
